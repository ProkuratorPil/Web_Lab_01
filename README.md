# Лабораторная работа №1: Проектирование и реализация RESTful API

## Краткое описание проекта

Этот проект представляет собой веб-приложение на Python, реализующее RESTful API для управления пользователями и файлами. Приложение написано с использованием фреймворка FastAPI, ORM SQLAlchemy, базы данных PostgreSQL, и контейнеризировано с помощью Docker и Docker Compose. Архитектура приложения разделена на слои: контроллеры (роутеры), сервисы, модели, схемы (DTO) и слой доступа к данным (CRUD). Реализованы такие функции, как мягкие удаления, пагинация, валидация данных на уровне DTO и хэширование паролей.

## Инструкция по запуску

1. Убедитесь, что у вас установлены [Docker](https://docs.docker.com/desktop/) и [Docker Compose](https://docs.docker.com/compose/install/).
2. Склонируйте репозиторий.
3. Создайте файл `.env` в корне проекта и укажите в нем настройки подключения к БД (см. `.env.example` ниже).
4. Откройте терминал в папке проекта.
5. Выполните команду:
   ```bash
   docker-compose up --build
   ```
   Приложение будет доступно по адресу `http://localhost:4200`.
## Пример файла переменных окружения (.env.example)

```ini
DB_USER=student
DB_PASSWORD=student_secure_password
DB_NAME=wp_labs
DB_HOST=localhost # или 'postgres', если используется внутри docker-compose
DB_PORT=5432

```

## Описание API

### Эндпоинты пользователей (`/users`)
| Метод  | URI           | Описание                                              | Статус успеха  |
| ------ | ------------- | ----------------------------------------------------- | -------------- |
| GET    | `/users`      | Получить список активных пользователей (с пагинацией) | 200 OK         |
| GET    | `/users/{id}` | Получить активного пользователя по ID                 | 200 OK         |
| POST   | `/users`      | Создать нового пользователя                           | 201 Created    |
| PUT    | `/users/{id}` | Полностью обновить пользователя                       | 200 OK         |
| PATCH  | `/users/{id}` | Частично обновить пользователя                        | 200 OK         |
| DELETE | `/users/{id}` | Пометить пользователя как удаленного (Soft Delete)    | 204 No Content |

### Эндпоинты файлов (`/files`)

|Метод|URI|Описание|Статус успеха|
|---|---|---|---|
|GET|`/files`|Получить список активных файлов (с пагинацией, с фильтрацией по пользователю)|200 OK|
|GET|`/files/{id}`|Получить активный файл по ID|200 OK|
|POST|`/files`|Создать новую запись файла (предполагается, что файл физически уже сохранен)|201 Created|
|PUT|`/files/{id}`|Полностью обновить запись файла|200 OK|
|PATCH|`/files/{id}`|Частично обновить запись файла|200 OK|
|DELETE|`/files/{id}`|Пометить запись файла как удаленную (Soft Delete)|204 No Content|

### Параметры пагинации

Параметры пагинации передаются через Query String (например, `?page=1&limit=10`).

- **`page`**: Номер страницы (целое число > 0). По умолчанию: 1.
- **`limit`**: Количество элементов на странице (целое число от 1 до 100). По умолчанию: 10.

### Ответ с пагинацией

Ответ на `GET /users` или `GET /files` имеет следующий формат:

```json
{
  "data": [
    // ... массив объектов (пользователей или файлов) ...
  ],
  "meta": {
    "total": 100,
    "page": 1,
    "limit": 10,
    "totalPages": 10
  }
}
```

## Инструкция по запуску миграций

Миграции запускаются автоматически при старте приложения через команду в `CMD` Dockerfile: `alembic upgrade head`. При первом запуске `docker-compose up --build` миграции будут применены к пустой базе данных. Для ручного управления миграциями можно войти в контейнер приложения:

```bash
docker-compose up --build

docker-compose exec app
# Затем выполнить команды alembic, например:
# alembic revision --autogenerate -m "..."
# alembic upgrade head
```
